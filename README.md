# Priora — 청구항 기반 선행기술 검색 (MVP)

> 화면에 보이는 이름은 Priora, 파이썬 패키지 이름은 `patsearch` 다.

청구항 텍스트를 넣으면 구성 분해 → 불린 검색식 생성 → 검색 실행(히트 수에 따라 검색식 자동 수정) →
초록 스크리닝까지 하고, 결과를 HTML 리포트 한 장으로 만든다.

- 터미널에서 실행하는 Python 프로그램이다. 결과 리포트만 브라우저에서 본다.
- LLM 은 Claude Code CLI(`claude -p`)를 불러 쓴다. API 키가 필요 없고 CLI 로그인 계정을 쓴다.
- 특허는 EPO OPS(제목·초록·CPC 검색), 논문은 OpenAlex.
- 외부 패키지 없이 Python 3.11 표준 라이브러리만 쓴다.

## 준비

`.env.example` 을 `.env` 로 복사하고 EPO OPS 키를 채운다.

```powershell
Copy-Item .env.example .env
```

```powershell
python -m patsearch --check
```

## 화면으로 쓰기

```powershell
python -m patsearch.web
```

브라우저에 화면이 열린다 (`start-ui.bat` 을 더블클릭해도 된다). 이 PC 안에서만 접속되며, 창을 닫거나
Ctrl+C 를 누르면 꺼진다.

- 화면 위 가운데의 두 탭 **새 검색 / 구성대비**로 할 일을 고른다. 왼쪽 위 Priora 를 누르면 첫 화면(새 검색)으로 간다.
- **새 검색**: 청구항을 붙여 넣고 검색을 누른다. 기준일은 "기준일 적용"을 켰을 때만 쓰인다.
- **구성대비**: 청구항과 인용발명 PDF 를 한 화면에서 넣고 시작한다(아래 "구성대비" 참고).
- **설정**(왼쪽 아래): EPO·OpenAlex 키, LLM CLI, 분석 모델, 스크리닝 모델, 스크리닝할 특허 수. 키는 `.env` 에,
  나머지는 `settings.json` 에 저장되며 터미널 실행도 같은 값을 기본으로 쓴다. 저장된 키는 화면에 다시
  표시되지 않는다. "저장하고 연결 확인"으로 LLM·EPO·OpenAlex 에 실제 요청을 보내 볼 수 있다.
- **진행 상황**: 5단계 표시와 진행 기록이 실시간으로 갱신된다. 중지했다가 이어서 실행할 수 있다.
- **검색 기록**: 왼쪽 목록에서 지난 검색을 열면 리포트가 그대로 나온다. 터미널로 돌린 검색도 같이 보인다.
- **삭제**: 기록 하나씩(× 또는 삭제 버튼) 또는 전체 삭제. `runs\` 의 해당 폴더가 지워지며 되돌릴 수 없다.
- EPO 요청 제한 때문에 검색은 한 번에 하나만 실행된다.

LLM CLI 는 Claude Code(`claude`), Codex CLI(`codex`), Antigravity CLI(`agy`), Gemini CLI(`gemini`)를
지원한다. 모델을 "기본값"으로 두면 각 CLI 의 설정을 따르고, 목록에 없는 모델은 "직접 입력"으로 넣는다.

- **CLI 연결**: 왼쪽 아래 "🔌 CLI 연결"에서 CLI 마다 설치·로그인 상태를 보고 로그인·로그아웃한다. 로그인은 새
  콘솔 창에서 진행되며, 마친 뒤 "상태 새로고침"을 누른다. 지금 쓰는 CLI 의 연결 상태는 왼쪽 아래에 늘 보인다.
- **중지**: 검색이나 구성대비가 도는 동안 빨간 "■ 중지" 버튼으로 멈춘다. 돌던 LLM CLI 프로세스까지 함께 끝난다.

엠블럼은 `patsearch/static/emblem.svg` 이고, 고친 뒤 `python tools\make_icons.py` 를 돌리면 파비콘이 다시
만들어진다(이때만 Pillow 필요).

### 구성대비 (청구항 1)

검색과 구성대비는 화면 위의 탭으로 나뉜다. "구성대비" 탭에서
청구항과 인용발명 PDF(끌어다 놓기 또는 파일 고르기, 12건까지)를 넣고 "구성대비 시작"을 누른다. 청구항 칸에는
독립항만 넣어도 되고 종속항까지 한꺼번에 붙여 넣어도 된다. 프로그램이 항을 나눠 가장 앞 번호의 독립항을 먼저
대비하고 종속항을 이어서 대비하며, 어떻게 나눠 읽었는지 입력칸 아래에 바로 보여 준다. 독립항 없이 종속항만
넣어도 된다(아래 "종속항만 대비"). 터미널에서는 다음과 같다.

```powershell
python -m patsearch.compare --claim claims\claim2.txt --docs a.pdf b.pdf --out compare_out\claim2
```

PDF 를 읽는 데 PyMuPDF 가 필요하다 (`pip install pymupdf`). 텍스트 층이 없는 스캔 PDF 는 쓸 수 없다.

역할 분담 (`patsearch/compare.py`):

- **LLM**: ① 청구항 구성을 특징으로 나누기(1회, 분석 모델) ② 문헌 × 구성마다 "이 특징이 이 문장에 개시되어
  있는가" 판정, 그 문장의 번역, 대응 이유 한 구절(스크리닝 모델) ③ 어느 문헌으로도 메우지 못한 특징만 다시
  본다. 분석 모델이 "이 특징이 없을 때 생기는 문제"와 "이 특징을 얻는 수단"을 풀어 쓰고(특징당 1회),
  스크리닝 모델이 문헌마다 그 문제·수단을 적은 문장을 짚는다. 끝으로 분석 모델이 짚인 문장들을 한 번에 보고
  근거가 안 되는 것(다른 종류의 데이터·결함)은 빼고, 남은 것에 직접/간접 강약을 매긴다(특징당 1회).
- 모델은 설정의 "분석 모델"과 "스크리닝 모델"을 쓴다. 터미널에서는 `--split-model`, `--model` 로 바꾼다.
- **프로그램**: PDF 에서 단락·문장 뽑기, 후보 문장 고르기, 주인용·결합 인용 선택, 양식 출력. 발췌는 문헌에서
  직접 잘라 넣으므로 원문과 항상 일치한다.

규칙:

- 구성의 특징이 모두 개시되면 "실질적 동일", 일부면 "일부 차이", 없으면 "차이".
- 주인용은 대응이 가장 많은 문헌. 주인용에 없는 특징은 다른 문헌으로 메우되 청구항 1 은 최대 3건까지.
- 메우는 순서: 그 특징을 그대로 개시한 문헌 → 없으면 도출 근거(문제·수단을 적은 문장)가 있는 문헌.
  도출 근거가 여러 문헌에 있으면 이미 쓰기로 한 문헌 → 가장 강한 근거 → 직접 → 간접 순으로 고른다.
  도출 근거로 메운 특징은 [차이점]에 `…는 문제와 …는 해결 수단이 기재되어 있고 … 통상의 기술자가 … 쉽게
  도출할 수 있습니다`로 쓴다. 수단을 적은 문장을 짚지 못하면 근거로 인정하지 않으며, 문헌 없이 주지관용이라고
  쓰지 않는다.
- `judgments.json` 에 `"source": "manual"` 로 직접 넣은 도출 근거는 다시 실행해도 유지된다.
- 영문 문헌은 `"번역" (단락 [0019]; "원문 발췌…")`, 국문 문헌은 `"발췌" (단락 [0019])`. 논문은 단락 대신 쪽 번호.
- 화면에서 인용발명 순서를 바꾸면 저장된 판정으로 양식만 다시 만든다(LLM 호출 없음).

### 구성대비 (종속항)

청구항 1 대비가 끝난 뒤, 구성대비 탭 아래쪽 "종속항 구성대비"에 종속항을 항 번호와 함께 붙여 넣고 시작한다.
PDF 는 다시 읽지 않고 청구항 1 때 저장한 문헌과 판정을 그대로 쓴다. 터미널에서는 `--docs` 없이
`--dependents` 를 준다.

```powershell
python -m patsearch.compare --claim claims\claim2.txt --out compare_out\claim2 --dependents claims\claim2_dep.txt
```

여러 항을 한꺼번에 붙여 넣으면 프로그램이 항별로 나눈다. 나누는 단서는 다음 순서로 찾는다.

1. 항 번호 표지: `[CLAIM 2]`, `[청구항 2]`, `【청구항 2】`, `<청구항 2>`, 줄 첫머리의 `청구항 2.` / `청구항 2`.
   줄을 바꾸지 않고 `… 방법. 청구항 3. 제2항에 있어서 …` 처럼 이어 붙여도 된다.
2. 표지가 없으면 줄 첫머리의 번호: `2. 제1항에 있어서 …`, `3) 제2항에 있어서 …`.
3. 번호가 아예 없으면 "제1항에 있어서"가 나오는 자리마다 나누고 순서대로 번호를 붙인다(붙인 번호를 알림으로
   보여 준다). 번호 붙은 항 뒤에 번호 없는 종속항이 이어져도 앞 항에 이은 번호를 붙인다.

"(삭제)"만 적힌 항은 건너뛴다. 번호가 없는 글에서는 중간에 낀 다른 독립항을 구별하지 못하므로, 독립항이 여럿이면
번호를 붙여 넣는다.

```
[CLAIM 2]제1항에 있어서, 상기 하나 이상의 머신 러닝 모델은 분류기를 포함하고, …, 방법.
[CLAIM 4]제1항 내지 제3항 중 어느 한 항에 있어서, 상기 분류는 …, 방법.
```

#### 종속항만 대비 (독립항 없음)

청구항 칸의 가장 앞 항이 종속항이면(예: 청구항 11~19 만 붙여 넣은 경우) 독립항 없이 종속항만 대비한다.
터미널에서는 `--claim` 없이 `--alone` 을 준다.

```powershell
python -m patsearch.compare --alone --dependents claims\claim2_dep.txt --docs a.pdf b.pdf --out compare_out\deps_only
```

- 항마다 **더한 구성만** 뽑아 인용발명 어디에 있는지 찾는다. 인용하는 항의 글이 없으므로 "상기 …"는 그 말뜻대로
  읽는다(함께 넣은 다른 항에 정의가 있으면 그 글을 맥락으로 쓴다).
- 모든 항이 "대비 기록 없음"이다. 인용하는 항에 어떤 인용발명을 썼는지 모르므로 **결론 줄은 쓰지 않는다.**
- 이어 쓸 인용발명이 없는 항은 독립항처럼 인용발명을 3건까지 쓰고, 넣은 항끼리 인용하면(제12항 → 제11항)
  앞 항의 인용발명을 이어 쓴 뒤 새 인용발명을 1건까지 더한다. 인용발명 번호는 종속항 구성을 많이 개시한 문헌부터 붙는다.
- 화면에는 구성별 판정표와 인용발명 순서 바꾸기가 없고 종속항 표와 양식만 나온다. 종속항 글을 고쳐 다시 돌리면
  PDF 는 다시 읽지 않는다.
- 번호가 없는 종속항만 넣으면 첫 항이 인용하는 항의 다음 번호부터 붙인다("제8항에 있어서 …" → 청구항 9).

역할 분담:

- **프로그램** (`patsearch/claims.py`): 항 나누기, 앞머리("제1항에 있어서", "제1항 내지 제3항 중 어느 한 항에
  있어서", "제1항 또는 제2항에 있어서", "청구항 1 내지 3 중 어느 하나에 있어서")에서 인용하는 항 읽기, 거슬러
  올라가며 닿는 모든 항 모으기(제3항 → 제2항 → 제1항). 독립항과 자신보다 뒤의 항을 인용하는 항은 빼고 그
  이유를 알린다.
- **LLM**: ① 종속항이 인용하는 항에 **더한 구성만** 뽑아 (2-1), (2-2) … 로 나누고, "상기 …"가 인용하는 항에서
  무엇을 가리키는지 풀어 쓴다(분석 모델, 종속항당 1회). 인용하는 항 전체를 맥락으로 함께 준다. ② 문헌 ×
  종속항마다 개시 여부, 그 문장의 번역, 대응 이유 한 구절(스크리닝 모델). ③ 어느 문헌에도 그대로 없는 구성은
  청구항 1 과 같은 방식으로 도출 근거를 찾는다.
- **프로그램**: 구성마다 인용발명 배정, 인용발명 번호, 발췌, 양식, 결론.

규칙:

- 인용하는 항에 쓴 인용발명은 그대로 이어 쓰고(번호가 앞선 것부터 찾는다), 거기에 없는 구성에만 새 인용발명을
  종속항 하나에 최대 1건 더한다. 인용발명 번호는 청구항 1 부터 하나로 이어진다.
- 여러 항을 택일로 인용하면 인용하는 항들의 인용발명을 합쳐서 본다.
- 인용하는 항의 대비 기록이 프로그램에 없어도 된다(예: 청구항 2·3 은 직접 대비하고 "제3항에 있어서"로 시작하는
  청구항 4 만 넣은 경우). 그 종속항이 더한 구성만 뽑아 인용발명 어디에 있는지 대비하고, 화면에 "대비 기록
  없음"으로 표시한다. 이때 청구항 1 본문만 맥락으로 쓰고, 청구항 1 의 인용발명에서 먼저 찾은 뒤 새 인용발명을
  1건까지 더한다. 인용하는 항에 어떤 인용발명을 썼는지 모르므로 결론 줄은 쓰지 않는다. 인용하는 항 가운데
  일부만 기록이 있으면 기록이 있는 항을 기준으로 대비한다.
- 양식: `제1항에 있어서 청구항 2의 구성 (2-1)에 대해 인용발명 1에는 "번역" (단락 [0022]; "원문 발췌…")는 구성이
  기재되어 있고 인용발명 1은 …므로 청구항의 "…를 포함"하는 구성에 대응됩니다`. 따옴표 안의 구성 이름과
  `인용발명 1은 …므로` 구절만 LLM 이 쓰고, 나머지는 프로그램이 채운다. 앞머리는 청구항에 적힌 그대로 쓴다.
- 구성을 찾지 못했거나 인용하는 항이 모두 결론을 못 낸 항이면 그 종속항의 결론은 쓰지 않는다.
- 청구항 1 의 인용발명 순서를 바꾸면 종속항 양식도 저장된 판정으로 다시 만든다(LLM 호출 없음).
- 인용발명 PDF 를 바꾸면 종속항 판정은 지워지고 입력한 종속항 글만 남는다. "구성대비 다시 실행"이 청구항 1 과
  종속항을 이어서 대비한다.
- 결과 폴더: `dependents.txt`(입력), `dependents.json`(인용 관계와 구성), `dep_judgments.json`(판정),
  `result.txt`(청구항 1 양식 뒤에 종속항 양식).

## 터미널로 쓰기

```powershell
python -m patsearch claims\claim1.txt --before 20230101
```

`--before` 는 기준일(보통 우선일)이다. 생략하면 공개일 제한 없이 검색한다.

결과는 `runs\<시각>-<파일명>\` 에 단계별 파일로 남는다.

| 파일 | 내용 |
|---|---|
| `01_elements.json` | 구성 분해, 구성별 검색어, CPC 후보 |
| `02_queries.json` | LLM 이 처음 만든 검색식 |
| `03_search_log.json` | 실행한 모든 검색식과 히트 수, 수정 이력 |
| `04_candidates.json` | 패밀리 단위로 중복 제거한 후보 문헌 |
| `05_screening.json` | 구성별 점수와 판단 근거 |
| `report.html` | 위 내용을 모은 리포트 |

## 검색식을 직접 고치고 싶을 때

단계 파일이 있으면 그 단계는 다시 계산하지 않는다. 그래서 중간에 끊고 손으로 고칠 수 있다.

```powershell
python -m patsearch claims\claim1.txt --stop-after queries
```

`01_elements.json`(검색어·CPC)이나 `02_queries.json`(검색식)을 편집한 뒤 이어서 실행한다.

```powershell
python -m patsearch --run runs\<폴더> --from search
```

`--from` 에 준 단계부터 뒤는 지우고 다시 만든다 (`elements`, `queries`, `search`, `screen`, `report`).

## 주요 옵션

| 옵션 | 기본 | 뜻 |
|---|---|---|
| `--max-hits` | 400 | 검색식 하나의 히트 수 상한. 넘으면 LLM 이 좁혀서 다시 쓴다 |
| `--min-hits` | 20 | 이보다 적게 걸리면 결과는 쓰되, 넓힌 검색식을 하나 더 만든다 |
| `--rounds` | 2 | 0건·과다·소량·문법오류 검색식을 고쳐 쓰는 반복 횟수 |
| `--per-query` | 100 | 검색식 하나에서 가져올 문헌 수 |
| `--max-screen` | 150 | 스크리닝할 특허 패밀리 수 (여러 검색식에 걸린 것부터) |
| `--model` | CLI 기본 | 구성 분해·검색식용 모델 |
| `--screen-model` | haiku | 초록 스크리닝용 모델 |

## EPO 요청 제한

EPO OPS 는 분당 검색 횟수를 제한하고, 서버가 바쁠수록 허용치가 줄어든다. 넘기면 "로봇"으로 판정되어
10~15분간 검색이 막힌다. 프로그램은 응답 헤더의 허용치에 맞춰 요청 간격을 조절하고(기본 3초 이상),
막히면 `--max-wait`(기본 120초) 안에서는 기다렸다 재시도한다. 그보다 오래 막히면 멈추고 이어서 실행할
명령을 알려 준다. 받은 응답은 `.cache\` 에 남으므로 다시 실행하면 이어서 진행된다.

기다렸다가 끝까지 돌리고 싶으면 대기 한도를 늘린다.

```powershell
python -m patsearch --run runs\<폴더> --max-wait 1500
```

## 한계

- EPO OPS 는 제목·초록·서지만 검색한다. 청구항·명세서에만 있는 표현은 걸리지 않는다.
- 한국 문헌은 영문 초록이 DB 에 있는 경우에만 걸린다.
- 스크리닝 점수는 초록만 본 1차 선별이다. 전문 대비(구성 대비표)는 아직 없다.
- 프롬프트는 `patsearch/prompts.py` 한 파일에 있다. 검색식 품질을 바꾸려면 여기를 고친다.
